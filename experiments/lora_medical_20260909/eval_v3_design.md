# v3 评估系统设计：适配小参数模型的量化评测标准

> 建立时间：2026-09-10 | 状态：设计已定稿，待实现
> 触发原因：首次云端全流程（v2 评估系统）实测数据暴露评测方式与模型量级不匹配

---

## 1. 背景：为什么需要 v3

### 1.1 首跑实测暴露的问题（真实数据，存档自 2026-09-10 首跑）

| 指标 | Base 基座 | LoRA 微调 | 问题 |
| :--- | :---: | :---: | :--- |
| MCQ 正确率 | 3.00% (3/100) | 1.00% (1/100) | 远低于随机水平 20% |
| MCQ 无效回答数 | 89 | 91 | ~90% 无法解析出选项 |
| MedQA 复读机式回答占比 | 17/30 | 19/30 | 无限重复同一片段 |
| 验证集 Loss | 1.5740 | 1.4575 (**-7.4%**) | ✅ 唯一有信息量且改善的指标 |

### 1.2 根因分析

抽样原始回答确认：模型在**续写题目、重列选项、陷入复读**，而非"答题"。典型案例如 base mcq_001 实际输出了"正确答案是D"，但前缀先啰嗦了一段选项列表，被保守解析器（正确地）判为无效。

**结论：v2 的"生成 + 严格解析"模式，在 64M 模型上测量的是"指令遵循能力"，不是"医学知识"。** 而指令遵循恰是此量级模型的能力盲区，导致 MCQ 指标信息量归零。LoRA 训练本身健康（val_loss 单调下降、平台期收敛、无过拟合信号），瓶颈不在训练，在评测适配。

### 1.3 v3 设计原则

> **用模型做得到的方式，测量它知道的东西。**

- 每一层评测都只依赖 64M 模型能力范围内的行为，不再以"听懂复杂指令"为前提
- 知识与格式解耦：能自动、确定、可复现的绝不依赖生成质量
- 全部自动化指标追求 **base 与 lora 可比**；绝对水平参考随机基线解读

## 2. 四层量化评估体系

### 第一层：医学知识 —— MCQ logprob 评分（最核心，替代生成式 MCQ）

**方法：选项概率对比，完全不生成文字。** 同一道题，将每个选项依次"填入"答案位置，用模型前向计算各选项的条件概率，取 argmax 作为预测：

```
prompt = 题干 + 选项列表 + "答案："        # 模板与 v1 题集问法保持一致
score(X) = logprob(下一个 token 为 "X")     # X ∈ {A, B, C, D, E}
预测 = argmax_X score(X)
```

**关键设计点：**

- 标准做法（lm-eval-harness 评 MMLU/基座模型的方式），专用于无指令遵循能力的小模型
- **100 道题道道有结果**，"无效回答"桶消失；纯前向计算，无采样、无解析器、完全确定
- 随机基线 = 20%，首次使 MCQ 数字可解读：核心结论是 `lora 正确率 − base 正确率`，而非绝对分
- 实现变体（后续可选）：选项拼完整答案文本打分时，**必须按 token 数归一化**，否则短选项系统性占优；字母版无此问题，先实现字母版
- 输出落盘 `mcq_scores.jsonl`：每题记录 5 个选项的 logprob、预测选项、是否正确，保持与 v2 同级的可审计性

### 第二层：分布拟合 —— 双路 val_loss

| 指标 | 数据 | 用途 |
| :--- | :--- | :--- |
| 医学 val_loss（已有） | `data/v2/val.jsonl`，固定模板（augment=False） | 衡量医学分布拟合，首跑已验证有效（-7.4%） |
| **通用 val_loss（新增）** | 从原 full_sft 通用 SFT 数据抽取约 100 条，固定为 `data/v2/general_val.jsonl`，同样 augment=False | **监测灾难性遗忘**：医学 LoRA 对通用对话能力的侵蚀程度 |

解读：医学 val_loss ↓ 且通用 val_loss 微涨为正常；通用 val_loss 暴涨（阈值建议 +5%）说明 LoRA 用力过猛。

### 第三层：生成健康度 —— 把"复读机"变成数字

长回答（MedQA 30 题 + General 10 题）继续生成，但第一阶段只量化"说没说人话"，全部自动计算：

| 指标 | 算法 | 首跑参考值 |
| :--- | :--- | :--- |
| 复读率 | 任一 30 字符片段在回答中出现 ≥3 次即判定（首跑统计即用的此启发式，固化进 run_eval） | base 17/30, lora 19/30 (medqa) |
| distinct-2 | 不同 2-gram 数 ÷ 总 2-gram 数 | 越低越复读 |
| 截断率 | 生成长度顶到 max_new_tokens 的回答占比 | 首跑 ≈ 1/30 |
| 平均长度 | 字符数 | base 541 / lora 423 (medqa) |

**前置动作**：生成配置引入 `repetition_penalty ≈ 1.15`。注意——生成配置属于对比一致性校验项，改动后 base 与 lora 必须**用同一新配置各重跑一遍**，禁止与旧产物混比。

### 第四层：内容相关性 —— 粗粒度量化 + 人工兜底

64M 模型的医学事实性必然差，内容评分只追求两侧可比：

- **字符级 ROUGE-L**（LCS F1）：模型回答 vs 参考答案的词汇重叠度。粗暴但确定、可复现；用纯 Python 实现 LCS，**不引入新依赖**（云端环境已验证的最小依赖集不动）
- **人工临床评审保留**（对比报告现有栏目不动），但**必须排在第三层达标之后**——回答还是复读机时不浪费评审时间

## 3. v3 记分卡（对比报告新增板块）

| 维度 | 指标 | 解读方式 | 方向 |
| :--- | :--- | :--- | :--- |
| 医学知识 | MCQ logprob 正确率 | 对随机 20% 基线；核心看 lora − base 差值 | 越高越好 |
| 医学分布拟合 | val_loss（医学） | 已有，首跑 -7.4% | 越低越好 |
| 通用能力保持 | val_loss（通用） | 涨幅越小越好，警戒 +5% | 越稳越好 |
| 生成健康度 | 复读率 / distinct-2 / 截断率 | lora 不应劣于 base | 越低越好 |
| 内容相关性 | ROUGE-L | lora 应高于 base | 越高越好 |
| 临床质量 | 人工评审 | 最后过一遍 | — |

**LoRA 有效的验收标准**：① MCQ logprob 正确率 lora > base；② 医学 val_loss 下降（已达成）；③ 通用 val_loss 涨幅 < +5%；④ 复读率不劣于 base。四条全过才算"微调有正向价值"。

## 4. 实施阶段（按信息量增量 ÷ 实现成本排序）

### Phase 1（最高优先）：MCQ logprob 评分
- `run_eval.py` 增加 `--mcq-score logprob` 模式：对每题 5 个字母各做一次前向打分，取 argmax
- 产物 `mcq_scores.jsonl` + summary 增加 `mcq_logprob_metrics`；对比报告适配新板块
- 验收：100/100 题可评分、无 invalid 桶；用首跑权重重跑 base/lora 即得首个可读 MCQ 对比
- 题集（`eval/v1`，manifest 锁定）与生成配置均不变，与历史产物完全可比

### Phase 2：生成健康度 + repetition_penalty
- 固化复读率/distinct-2/截断率/平均长度四项统计进 run_eval
- `repetition_penalty=1.15` 作为新生成配置，base/lora 双侧同配置重跑

### Phase 3：双路 val_loss + ROUGE-L
- 制备 `general_val.jsonl`（约 100 条，固定、标注来源与 md5）
- 字符级 ROUGE-L（纯 Python LCS，无新依赖）
- 之后方可进入人工临床评审

---

## 5. 兼容性与约束

1. **题集不动**：`eval/v1`（100 MCQ + 30 MedQA + 10 General + manifest）保持锁定，v3 只改"评分方式"，不改"考题"
2. **一致性校验继承**：v2 已实现的 base/lora 身份链校验（权重 md5、题集 md5、val 集 md5、device/dtype、生成配置）继续强制生效；新增配置项纳入校验范围
3. **val_loss 路径不动**：SFTDataset(augment=False) 固定模板口径保持不变，v3 与 v2 的 val_loss 可直接纵比
4. **冒烟与跳过机制不变**：run_cloud.sh 的 7 步流程、完成标记、日志落盘全部复用；v3 各阶段实现后补冒烟用例与本地单测

## 6. 首跑基线存档（v2 系统产出，作为 v3 的历史对照）

> 2026-09-10 首跑：5000 条医学数据，1 epoch = 625 steps，lr 1e-4，LoRA 0.393M 参数（0.61%），RTX 4090 / bfloat16

- 训练 val_loss 曲线：1.5743 (step 0) → 1.4578 (step 625)，单调收敛、平台期形态
- 评估 val_loss：base 1.5740 / lora 1.4575（与训练日志 step 0 数值一致，证实固定模板修复生效）
- MCQ（生成式，v2 口径，仅供历史对照）：base 3% / lora 1%，无效 ~90% —— **v3 起此口径退役，仅保留 logprob 口径**
- MedQA 复读率：base 17/30 / lora 19/30
